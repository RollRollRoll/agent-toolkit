# 通知插件采用无常驻进程的单向发送，失败即丢弃

通知插件由 Agent hook 每次事件触发一个短进程，直接调用 Telegram Bot API 单向发送，不部署服务器、不运行常驻 Bot 进程。发送失败时有限重试（最多 2 次、总超时默认 10 秒，可配置），之后只写本地日志并正常退出，不缓存补发。

## 考虑过的方案

- **常驻 Bot / 本地守护进程**：可支持 Telegram 内审批、回复、失败补发，但违背「无需服务器或常驻后台服务」，且审批代答会干预 Agent 原有审批流程。
- **本地队列 + 下次触发时补发**：能减少丢失，但引入状态文件与并发写竞争，延迟的通知对「及时回来处理」价值很低。

## 后果

- 通知可能丢失，这是有意接受的取舍：保证 Agent 执行不受影响优先于送达率。
- 双向交互（审批、回复驱动 Agent）需要推翻本决策，引入常驻组件。
