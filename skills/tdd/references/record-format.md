# 执行记录 — 结构与写法

> 用途：`tdd` 闭环的证据落盘格式。`scripts/tdd-record.sh` 会按这个结构建好文件，
> 之后**边做边追加**；本文件说明每一段写什么、怎么才算证据。

## 为什么必须落盘

- **上下文会被压缩**：留在对话里的红 → 绿输出会消失，落盘的还在。
- **调用方要核证据**：execute 的闸门一读它判定"这个任务真做完了"；
  整体验收的 review 也拿它当输入。
- **追写不算证据**：跑完一整轮再凭印象补写的是回忆。每转一次红或绿就写一次。

## 结构

````markdown
# TDD 执行记录：[名称]

## 需求依据

- seam：[测在哪个可观察边界上]
- 验证方式：[命令]

## 行为 1：[一句话说清验的是什么行为]

- 红：`[测试命令]`
  ```
  [失败输出，保留关键几行]
  ```
  为何预期失败：[行为缺失在哪 —— 必须是行为缺失，不是语法 / import / 环境错]
- 绿：`[同一条测试命令]`
  ```
  [通过输出]
  ```

## 行为 2：…

## 收尾验证

`[验证命令 + typecheck]`
```
[完整输出，含告警]
```

## 改动文件

- [路径]：[改了什么]

## 疑虑

- [看到但按规则没动的结构问题 —— 交回调用方]
````

## 每段的判据

| 段落 | 什么算写对了 |
|---|---|
| 行为标题 | 说清**验的是什么行为**，不是"改 xx 文件"、"加个函数" |
| 红 | 有命令、有失败输出、有**为何预期失败**；失败原因是行为缺失 |
| 绿 | 与红**同一条命令**，有通过输出 |
| 收尾验证 | **完整跑一次**的输出，含告警；不是循环中途某次的输出 |
| 改动文件 | 路径 + 改了什么，供调用方核范围 |
| 疑虑 | 结构问题原样记着，没有顺手改掉 |

## 常见写坏

- 只有绿没有红 → 按 SKILL.md「交付判据」重做一遍红 → 绿，或写明做不到并告知调用方。
- 红的失败输出是 `ModuleNotFoundError` / 语法错 → 那不是红过，是环境没准备好，先修掉重跑。
- 收尾验证抄了循环中途的输出 → 那时的代码不是最终代码，重跑。
- 记录写成"测试都过了" → 没有命令与输出就没有判据。
