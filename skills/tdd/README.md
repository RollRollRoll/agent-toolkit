# TDD

## 用途

**composable 层**的红 → 绿闭环能力单元：在**已约定的 seam** 上，把一段行为改动做成一串
"失败测试 → 最小实现 → 验证"的闭环，并**当场**把每一次红 / 绿的命令与输出落进执行记录。

它交付的不是"代码写完了"，而是**可核对的证据**：每个行为都有实现前的失败输出（含"为何预期失败"）
和实现后的通过输出，收尾完整跑过一次验证命令。调用方拿这份证据判定"真的做完了"。

## 触发场景

- "用 TDD 实现这个功能 / 先写测试再写实现 / 走红绿循环"
- "修这个 bug，先写复现测试"
- 由 **execute-task**（workflow 层）在阶段 2 每个任务内调用。
- 不适用：给已写完的实现事后补测试；只跑测试不改代码；纯定位 bug 不改行为；代码评审（那是
  **review-changes**）；任务拆分（那是 **split-task**）。

## 调用契约

| 方向 | 内容 |
|---|---|
| 传入 | 需求依据（行为 / 验收标准 / 精确值）、**seam**、验证方式、执行记录路径（可选） |
| 取回 | 证据齐否、改动文件清单、疑虑、记录路径；卡住回 BLOCKED |
| 不做 | 不 commit、不改 checkbox、不动 git 状态、不排任务、不改需求、不做整体审查 |

## 使用方式

把本目录下的 `SKILL.md`、`references/` 和 `scripts/` 复制到目标平台的 skill 目录
（Claude Code：`.claude/skills/tdd/`；Codex：`.agents/skills/tdd/`）即可直接使用；
若 `scripts/` 下脚本丢失可执行权限，按所在环境的权限变更规则取得确认后，再补一次 `chmod +x scripts/*.sh`。

调用本 skill 是**加载执行纪律，不是派 subagent**——调用方在自己的上下文里走完闭环。

## 目录说明

- `SKILL.md`：skill 主体（平台原生格式，含 frontmatter）。
- `references/test-quality.md`：好测试的五条判据、三个反模式（实现耦合 / 同义反复 / 水平切片）的识别信号与改法、mock 边界。
- `references/record-format.md`：执行记录的结构、每段判据与常见写坏。
- `scripts/tdd-record.sh`：建工作目录（点目录自动自忽略）+ 按标准结构建记录文件（已存在不覆盖），打印路径。
