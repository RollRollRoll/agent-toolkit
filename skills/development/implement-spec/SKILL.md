# Implement Spec

输入是一份 spec，以及描述如何实现它的关联工单。
目标是在**一条集成分支上实现整份 spec，交付一个可审查的 PR**。

工单构成带阻塞关系的**任务图**。**前沿（frontier）**是所有前置工单已完成、
且尚未开始的工单集合；优先并行执行其中的工单。
**单张工单完成只是进度节点，主 agent 应继续调度，直到全部工单完成。**

与子 agent 的通信以**上下文指针**为主：传递 spec、工单、调研笔记的路径或 URL，
以及相关提交标识；已有材料通过引用获取。条件允许时让实现子 agent 在后台运行，
充分利用可用并发。

## 流程

1. **读取 spec 和全部关联工单**，理解任务图、阻塞关系与已有完成状态。
   工单的读取方式遵循项目已有的 `docs/agents/issue-tracker.md`。

2. **按需派探索子 agent**，调查工单涉及的代码或外部文档。
   确保它能将 Markdown 笔记写到仓库之外、后续子 agent 都能访问的位置，
   并将路径交给实现子 agent。

3. **创建集成分支和草稿 PR**，记录分支的基线提交。
   PR 声明合并后关闭 spec issue 和关联工单；本地文件工单用路径引用。

4. **为前沿中的工单派实现子 agent**，每个使用独立 worktree 和独立分支，
   从包含其全部前置成果的集成分支提交开始工作。
   分配时记录工单已开始，避免重复派发；子 agent 完成后向主 agent 返回
   分支、提交与验收结果，由主 agent 继续调度。

5. **每当一个实现子 agent 完成，派合并子 agent** 将其成果合入 PR 分支。
   对同一集成分支的合并串行进行；合并并通过相关验证后，才将工单记为完成。

6. **重新计算前沿，立即调度新解锁的工单**，持续重复步骤 4–6。
   单张工单完成后无需逐单确认。有运行中的子 agent 时等待其结果；
   某张工单受阻时继续处理其他不受影响的工单。
   如果仍有未完成工单，但没有可执行工单和运行中的子 agent，报告阻塞原因并暂停。

7. **全部工单完成后，运行整体验证并调用 `code-review`**，
   提供步骤 3 的基线提交、完整 spec 和关联工单引用，审查整个 PR 分支。
   将审查发现的问题交给一个实现子 agent 统一修复，合入后验证修复结果。

8. **将 PR 标为可审查**，确认完整 spec 已实现、验证通过且审查问题已解决。

9. **清理本次创建的实现子 agent worktree**，先确认成果已合入且没有未保存的工作。
   最后汇报 PR 链接、工单完成情况与验证结果。

提交、推送、创建或更新 PR、清理 worktree 等操作遵循当前会话的授权和仓库规则；
已有明确授权在其范围内持续有效，尚未授权的必要操作应在执行前取得确认。
