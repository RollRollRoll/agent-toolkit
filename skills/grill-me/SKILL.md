# Grill Me

不停地盘问用户，直到你们达成共同理解。把它建模成一棵**设计树**：每个决策都会分叉出挂在它下面的决策。

按**轮次**推进这棵树。**frontier（可问边界）**是所有前置已经定下来的决策：那些你**现在**就能问、
不必猜测尚未听到的答案的问题。把整个 frontier 在一轮里问完：给每个问题编号，并给出你的推荐答案。
然后等用户回答，再进入下一轮。

每个问题按以下格式：

```
❓ **Q1** - **<问题标题>**：<问题正文，可以有多段，可以列出多个选项>

➡️ <你的推荐答案>
```

用户每一轮的回答都会重塑这棵树：定下来的决策把 frontier 向外推，解锁原本依赖它们的问题。
重新计算 frontier，问下一轮。一个问题如果依赖本轮还开着的另一个问题，它属于**更后面的**轮次，
不属于这一轮。

查**事实**是你的活，永远不是用户的活。当 frontier 上的某个问题需要环境里的事实（文件系统、工具等），
派一个 subagent 去查；凡是你自己查得到的，都不要问用户。不要因此阻塞：正在跑的探查是一个未定的前置，
所以只有它下游的问题等 subagent 回报，frontier 上其余的问题现在就问。**决策**是用户的：
逐条摆到他面前，然后等。

frontier 空了，这次会话就结束了：设计树的每个分支都访问过，没有任何东西被默默假设掉。
在用户确认你们已经达成共同理解之前，不要对它采取行动。
