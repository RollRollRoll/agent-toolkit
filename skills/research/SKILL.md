# Research — 一手来源调研

## 目标

把资料检索和阅读委托给一个后台 agent，让当前 agent 能继续处理其他工作。最终必须在仓库中留下一个可复查的 Markdown 调研文件，而不只是聊天摘要。

## 工作流程

1. 明确要回答的问题、调研边界和当前仓库根目录。先查找仓库已有的调研、设计或笔记目录，沿用其文件位置和命名方式。
2. 如果没有现成约定，选择简洁合理的位置，例如 `docs/research/<topic>.md`，并在交付时说明路径。不要为了单篇调研引入额外目录层级或索引体系。
3. 启动一个后台 agent，向它提供：准确的问题、边界、输出文件路径、当前仓库上下文，以及下面的来源与写作要求。只把调研任务委托出去，不让多个 agent 同时写同一文件。
4. 在后台 agent 调研期间继续完成当前任务中其他不依赖调研结论的工作；不要凭空预判调研结果。
5. 后台 agent 完成后，检查输出文件存在且只有预期改动，并抽查关键结论是否有直接来源支撑。缺少来源、来源层级不够或结论超出证据时，要求补查后再交付。

如果当前环境无法启动后台 agent，则在当前 agent 中执行同样的调研流程，并明确说明未能后台委托；不要因此降低来源或落盘要求。

## 后台 agent 的任务

1. 优先查阅拥有该事实的一手来源，例如官方文档、标准或规范、项目源码、维护者发布记录和第一方 API。二手文章只能用于发现线索，不能作为可由一手来源验证之结论的最终依据。
2. 将每项重要结论追溯到直接来源。涉及版本差异、时效性或相互冲突的资料时，记录适用版本、日期和无法消解的不确定性，不把推断写成事实。
3. 把结果写入指定的**单个 Markdown 文件**。文件至少包含：调研问题、结论摘要、带逐项来源的发现，以及仍未确认的缺口；简单问题可以合并章节，但不能省略引用。
4. 引用应指向能直接支撑相邻结论的具体页面、规范章节、源码文件或固定版本链接。避免只列一个与正文无法对应的笼统参考资料清单。
5. 除指定调研文件外，不修改代码、配置或其他文档，也不执行调研结论所建议的实现。

## 完成标准

- 指定问题得到直接回答，边界外内容没有扩张成泛泛综述。
- 关键事实均可由高可信一手来源复核，推断和未知项已明确标注。
- 仓库中只有一个承载本次结论的 Markdown 调研文件，且位置符合既有约定或已在交付中说明。
- 最终回复给出文件路径、一两句核心结论和仍存在的重要缺口，不重复粘贴整篇报告。
