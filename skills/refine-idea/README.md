# Refine Idea

## 用途

在动手写 spec 或代码之前，把一个还没想透的想法 / 期望，通过协作对话
打磨成一个**边界清晰的可执行概念**：锁定"做什么"和"不做什么"，
但刻意不产出技术方案、不拆解任务。

它填补"挖意图"和"写 spec"之间的空档：止步于概念边界，把确认过的
概念交还用户，不自动往下进入实现。

阶段 1「挖意图」自己用 Q+GUESS 一次一问；阶段 2「照亮边界」把提问交给 composable 层的
**[grilling](../grilling/)**，范围限定为**只展开概念层**，技术选型 / 架构 / 实现路线剪给下游
make-design。

## 触发场景

- "我想做一个 X（但还没想清楚）/ 我有个想法，帮我理一理"
- "帮我把这个需求打磨打磨 / 这个点子靠谱吗"
- "在动手前先把要做什么、不做什么定下来"
- 需求宽泛、模糊，或夹带 "scalable / 干净的架构 / 业界标准做法"
  这类"听上去应该想要"的词，需要先厘清真实意图。
- 不适用：需求已明确可直接写 spec / 编码；要的是技术选型 / 架构 /
  实现方案；已在写代码 / 调 bug / 评审；以及任何非交互场景
  （CI / 定时任务 / 自治循环）。

## 调用契约（阶段 2 → grilling）

| 方向 | 内容 |
|---|---|
| 传入 | 阶段 1 钉死的根节点、范围＝只展开概念层、阶段 0/1 已定事实与约束、交回形态＝做 / 不做两份清单 + 挂起 + 剪枝 |
| 取回 | 概念层已定归属、被剪掉的分支（带进阶段 3 说明）、隐藏假设与风险、用户确认状态 |

阶段 2 的出口判据因此是**概念层 frontier 空**，而不是达标即停——达标即停只管阶段 1。

## 使用方式

将本目录下的 `SKILL.md` 和 `references/` 复制到目标平台的 skill 目录
（Claude Code：`.claude/skills/refine-idea/`；Codex：`.agents/skills/refine-idea/`），
**并同时安装 [grilling](../grilling/)**——阶段 2 依赖它。

## 目录说明

- `SKILL.md`：skill 主体（平台原生格式，含 frontmatter）。
- `references/lenses.md`：阶段 2「照亮边界」用的思维透镜清单。
- `references/concept-note.md`：阶段 4 落盘时用的概念单模板。
