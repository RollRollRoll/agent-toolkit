# 问卷模板 — 落盘用

> 落到当前目录的 `to-questionnaire-<slug>.md`（用户指定路径则用用户的）。
>
> **定位**：这是一份**探询式问卷**——用户缺上下文，收件人有上下文。
> 不是需求文档，不是会议纪要，也不是用户自己的调研笔记。
>
> **排序铁律**：最重要的问题排最前。异步作答可能只有一次机会，对方也可能填到一半就停。
> 问题超过一小把时，按主题拆 `##` 小节，组内仍按重要性排序。

## 模板

```markdown
# <问卷标题>

**目的：** 这份问卷为什么存在，以及押在它上面的那个决策是什么。

**发件人：** <用户> — **收件人：** <收件人> — **答案的用途：** <会被用到哪里>

## 背景

一段话，把一个"不在用户脑子里"的收件人带进情境。够他答好即可，不要写成一页纸。

## 如何作答

截止时间，以及大致要花多少工夫。说明：**部分作答和"不知道"同样有用**——
不确定的地方请标出来，不要直接跳过。

## <主题小节标题>

每个主题一个 `##` 小节。小节内按重要性排列问题。

每个问题只承载一个意思（禁止复合问题），下面紧跟一个空的引用块作为答题位；
只在问题**可能被误解**或**容易被一句话敷衍过去**时，才加一行斜体的"为什么重要"。

### 系统上线时预计要扛多大流量？

*为什么重要：它决定我们现在就按突发流量做容量，还是先放一放。*

>

### <下一个问题>

>

## 还有什么？

收尾的兜底问题：有没有什么我们没问到、但你觉得我们应该知道的？
```

## 写完自查

- [ ] 用户在步骤 2 列出的每一项，都有问题覆盖？
- [ ] 问题顺序是**重要性优先**，不是想到的顺序？
- [ ] 总题数收敛在 **12 题以内**，且每题都能说清它如何影响"目的"里那个决策？
- [ ] 每个问题只有一个意思，没有"A 和 B 是怎样的？"这类复合问句？
- [ ] 每题下面都有答题位？
- [ ] "为什么重要"是克制使用的，不是每题都挂一句？
- [ ] `## 背景` 能让一个完全没参与过的人读懂并作答？
- [ ] 没有诱导性预设，也没有把用户的猜测写成既定事实？
- [ ] 有兜底的"还有什么？"一节？
