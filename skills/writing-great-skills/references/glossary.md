# 术语表：构建高质量 Skill

本术语表定义影响 Skill **可预测性**的核心概念。各术语按调用、信息层级、行为引导和剪枝分组；失败模式与对应修复手段放在相邻位置。

定义中的**粗体术语**也在本文件中有独立条目。

## 可预测性

Skill 让 agent 在每次运行中遵循相同过程的程度，而不是要求相同输出。头脑风暴可以稳定地产生不同答案，只要它每次都执行相同的发散与收敛纪律。调用、层级、引导和剪枝都服务于这一根目标。

_避免称作_：输出确定性、一致输出

## 调用

### 模型调用型

保留模型可见**描述**的 Skill。Agent 可以自主发现并触发它，人类仍可显式选择，其他 Skill 也能调用。它用持续的**上下文负载**换取可发现性。只有模型或其他 Skill 确实需要主动触达时才选择这种形态。

_避免称作_：能力、工具

### 用户调用型

模型不可见、只能由人类显式选择的 Skill。它没有上下文负载，但用户要承担记住它及适用时机的**认知负载**。其他 Skill 也不能调用它。

_避免称作_：命令、流程

### 描述

Skill 的机器可读触发入口，也是模型调用型 Skill 必须持续加载的顶层**上下文指针**。它负责定义触发分支，而不是重复正文。

_避免称作_：摘要、frontmatter

### 上下文指针

当前上下文中一段指向未加载材料的说明，同时编码“何时读取”的条件。描述是从上下文指向 Skill 的顶层指针，`SKILL.md` 中指向参考文件的链接是下一层指针。措辞决定触达可靠性；目标文件本身无法修复一个含糊指针。

_避免称作_：普通链接、导入

### 上下文负载

模型调用型 Skill 在每轮持续消耗的上下文成本，主要来自其描述及由此占用的注意力。它是限制模型调用型 Skill 数量和描述长度的主要因素。

_避免称作_：单纯 token 数

### 认知负载

用户调用型 Skill 让人类承担的记忆成本：有哪些 Skill，以及何时手动选择。它是保留人类主动权的代价，不需要一概消除；数量过多时用**路由 Skill**降低。

_避免称作_：模型开销

### 路由 Skill

一个用户调用型 Skill，列出其他用户调用型 Skill 及其适用场景，让用户只需记住一个入口。它只能提供导航，不能替用户调用那些模型不可见的 Skill。

_避免称作_：自动调度器

### 粒度

Skill 被拆分得多细。拆出更多模型调用型 Skill 会增加上下文负载；拆出更多用户调用型 Skill 会增加认知负载。只有独立调用价值或隔离后续步骤的收益足够大时，切分才成立。

_避免称作_：模块化本身

## 信息层级

### 信息层级

按照 agent 需要材料的即时程度排列内容：Skill 内**步骤**、Skill 内**参考资料**、经指针披露的参考资料。它决定内容应该内联还是下移，而不是规定一种固定文档布局。

_避免称作_：目录结构、排版

### 步骤

Agent 按顺序执行的动作，是存在流程时 `SKILL.md` 的主要层。每一步都以**完成判据**收口。Skill 可以没有步骤，只包含参考资料。

_避免称作_：所有说明、背景知识

### 参考资料

Agent 按需查阅的定义、事实、参数、示例和条件性规则。有步骤时它处于次级；无步骤时它可以构成整个 Skill，也是**渐进式披露**的主要候选。

_避免称作_：步骤、流程

### 外部参考资料

位于 Skill 系统之外、不能被调用的普通资料文件。多个 Skill 可以通过上下文指针共享它，适合存放不需要独立触发的共同知识。

_避免称作_：共享 Skill

### 渐进式披露

把只在部分分支需要的参考资料从 `SKILL.md` 下移到上下文指针之后，从而保护信息层级。它首先服务于注意力和可预测性，其次才是节省 token。

_避免称作_：任意拆文件、懒加载

### 共置

把同一概念的定义、规则和例外放在一起，让读取其中一部分时自然获得邻近信息。信息层级决定放多深，共置决定同一层里放在谁旁边。

_避免称作_：重复、简单分组

### 蔓延

_失败模式。_ Skill 中每一行都可能有效且唯一，但整体仍然过长，导致注意力稀释、阅读困难和维护成本上升。沿信息层级披露参考资料，或按分支、顺序拆分。

_避免称作_：沉积、重复

## 行为引导

### 分支

Skill 支持的一种独立使用方式。不同调用进入不同分支；所有分支都需要的内容应内联，只服务某些分支的内容适合披露。

_避免称作_：同义触发词

### 引导词

模型预训练中已有、能用少量 token 激活一组行为先验的概念。它在正文中锚定执行，在描述中锚定调用。重复引导词本身可以增强注意，但不应重复它的整段定义。

_避免称作_：任意关键词、口号

### 完成判据

Agent 判断一项工作是否结束的条件。清晰度决定能否抵抗**过早完成**，要求强度决定需要投入多少**下钻工作**。最佳判据既可检查，又在必要时明确要求穷尽覆盖。

_避免称作_：模糊目标、停止提示

### 下钻工作

Agent 在一个步骤内部完成的查找、阅读、验证和修改。它不是额外步骤，而是由强引导词和完成判据驱动的实际投入。判据只要求“给出一些结果”时，下钻工作通常会变薄。

_避免称作_：步骤数量、笼统的认真

### 后续步骤

当前步骤之后仍然可见的步骤。它们会把注意力拉向“赶快完成”，在当前完成判据模糊时诱发过早完成。

_避免称作_：当前步骤内容

### 过早完成

_失败模式。_ 当前步骤尚未真正达到完成判据，注意力却已滑向后续步骤。先把判据锐化为可检查条件；只有判据无法进一步清晰且确实观察到抢跑时，才通过真正的上下文边界隐藏后续步骤。

_避免称作_：所有覆盖不足、单纯下钻不足

### 否定式引导

_失败模式。_ 通过描述禁止行为来引导，反而把该行为激活到上下文中。优先直接描述目标行为；无法改写的硬约束应同时配对一个明确的正向动作，让注意力落在应该做什么上。

_避免称作_：任何必要约束

## 剪枝

### 单一事实来源

每个行为含义只存在于一个权威位置，因此修改行为只需改一处。**重复**是对这一状态的破坏。

_避免称作_：所有内容都塞进一个文件

### 重复

_失败模式。_ 同一含义拥有多个权威表达，增加维护和 token 成本，并把该含义在注意力中的权重抬得过高。合并解释，必要时只重复引导词这个 token。

_避免称作_：引导词复现、相关概念

### 相关性

一行内容当前是否仍然影响 Skill 的目标行为。它可能从未相关，也可能随实现和环境变化而失效。相关性不同于无效指令：一句话可以与任务相关，却仍不改变模型默认行为。

_避免称作_：是否写得正确

### 沉积

_失败模式。_ 旧内容因为添加容易、删除困难而逐层累积，使有效规则埋在过时材料之下。定期用相关性检查删除失效层。

_避免称作_：蔓延、重复

### 无效指令

_失败模式。_ 一句话没有改变模型相对于默认状态的行为，却仍占用上下文。逐句询问“删掉它，执行会不同吗？”答案为否时删除整句，或换成足够强、真正能改变行为的引导词。

_避免称作_：所有常识、单纯措辞不佳
