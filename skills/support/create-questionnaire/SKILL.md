# Create Questionnaire — 知情人问卷生成

把用户**一个人答不出来**的事，变成一份**问卷**：一份 Markdown 文档，用户可以异步发给某个人填，
也可以拿着它开一次会一起填完。知识在**收件人**手里，用户手里没有；问卷的唯一职责，是把那部分
知识从收件人身上挖出来。

**盘问"发送"，不盘问"主题"。** 只就用户**一定答得上来**的两件事访谈他：发给谁，要拿回什么。
问卷里的问题则全部对准**收件人知道、而用户不知道**的那段缺口。继续追问主题细节，只会把用户
逼到编答案，或者把问卷写成他自己的调研笔记——两种结果都让这份文档失去价值。

1. **发给谁？** 一次交换问清收件人的角色、专长，以及与用户的关系。这决定问卷的语气，
   以及文档必须自带多少上下文。**完成判据**：你说得出收件人是谁，以及他知道而用户不知道的是什么。

2. **要拿回什么？** 一次交换问清用户独自解决不了、必须从这个人身上拿到的**具体**决策或事实。
   "了解一下他们的技术栈"不算，"确定能不能直接调他们的 API，还是必须走文件交换"才算。
   **完成判据**：你手上有一份具体清单——用户填完这份问卷后，必须能做出哪些决定、确认哪些事实。
   清单里出现"还有一些""大概几条"这类未展开项时，追问到逐条具体再进入步骤 3；不得先起草再回头补。

3. **写问卷。** 按下面的文档结构起草，问题对准步骤 1–2 摸清的那段缺口，写到当前目录的
   `questionnaire-<slug>.md`（slug 取自主题；用户指定了路径就用用户的），然后报告路径。
   **完成判据**：文件已存在，且步骤 2 清单里的每一项都有问题覆盖。

## 文档结构

这是一份**探询式问卷**：用户缺上下文，收件人有上下文。问题**最重要的排最前**——异步意味着
你可能只有一次机会，对方也可能填到一半就停；超过一小把问题时按主题拆 `##` 小节，组内仍按
重要性排序。总题数收敛在 **12 题以内**：逐题自问"它的答案会不会改变『目的』里那个决策"，
答"不会"的删掉。覆盖清单不等于穷举维度，三十题的问卷对方大概率一题也不会认真填。

# <问卷标题>

**目的：** 这份问卷为什么存在，以及押在它上面的那个决策。

**发件人：** <用户> — **收件人：** <收件人> — **答案的用途：** <会被用到哪里>

## 背景

一段话，把一个不在用户脑子里的收件人带进情境。够他答好即可，不要写成一页纸。

## 如何作答

截止时间与大致工作量。说明部分作答和"不知道"同样有用：不确定的地方标出来，不要直接跳过。

## <主题小节标题>

每个主题一个 `##` 小节，组内按重要性排序。每个问题只承载**一个意思**（禁止"A 和 B 是怎样的？"
这类复合问句），下面紧跟一个空引用块作为答题位；只在问题**可能被误解**或**容易被一句话敷衍
过去**时，才加一行斜体的"为什么重要"——每题都挂一句会把文档撑成说明书，反而降低填写意愿。
不写"我们假设你们用的是 REST"这类诱导，也不把用户的猜测写成既定事实。

### 系统上线时预计要扛多大流量？

## 语言

问卷写给**收件人**看，默认中文；用户说明收件人使用其他语言时，整份文档用那种语言写，
包括小节标题。

只产出问卷：不要顺手去执行问卷背后的那个决策，也不要替用户把问卷发出去。
