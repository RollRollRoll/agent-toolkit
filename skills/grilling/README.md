# Grilling

## 用途

**composable 层**的访谈能力单元：把一个计划、设计或决定建成**设计树**，按**轮次**推进——
每轮把所有前置已定、当下问得动的问题（frontier）一次问完，每题编号并附推荐答案；
用户回答重塑树，重算 frontier，直到声明范围内的分支穷尽。

它交付的不是文档，而是一个状态：**范围内每个分支都被访问过，没有东西被默默假设掉**。

## 触发场景

- 由 **[grill-me](../grill-me/)**（人类专用入口）调用，范围＝全部展开、不剪枝。
- 由 **[refine-idea](../refine-idea/)**（workflow 层）在阶段 2 调用，范围＝只展开概念层。
- 模型自己需要就一份成形的方案与用户对齐时，可直接调用。
- 不适用：连"要解决什么问题"都还没定（那是 refine-idea 阶段 1，树只有一个未知根节点）；
  写实现；代码评审；以及任何无人实时应答的场景（CI / 定时任务 / 自治循环）。

## 调用契约

| 方向 | 内容 |
|---|---|
| 传入 | 访谈对象 + 已定根节点、**范围（哪些分支展开 / 剪给谁）**、已定事实与约束、交回形态 |
| 取回 | 已定决策清单（含理由）、树的终态（穷尽 / 挂起 / 剪枝）、暴露的假设与风险、用户是否已显式确认 |
| 不做 | 不实现、不落盘、不替用户决策、不自动调下游 skill、不在非交互场景运行 |

**范围缺省是全部展开**。调用方要限层就必须给出判据，被剪掉的分支仍要在取回时报告——
没说破的分支正是"默默假设掉"的东西。

## 与参考实现的差异

移植自 [mattpocock/skills](https://github.com/mattpocock/skills) 的 `productivity/grilling`
（MIT，见 `LICENSE.upstream`）。机制（设计树、轮次、frontier、事实由 subagent 查且不阻塞、
frontier 空即结束、确认前不行动）与上游逐条对齐，`❓` / `➡️` 格式一致。差异：

- 全部改写为中文。
- 增加上游没有的**调用契约**与**范围 / 剪枝**约定，使它能被 `refine-idea` 限定在概念层调用；
  `grill-me` 传"不剪枝"时行为与上游等价。
- 补**挂起**处理（用户暂时无法决定的节点及其下游退出 frontier）与反例一节。

## 使用方式

将本目录复制到目标平台的 skill 目录（Claude Code：`.claude/skills/grilling/`；
Codex：`.agents/skills/grilling/`）。`grill-me` 与 `refine-idea` 依赖它，装那两个就要装它。

调用本 skill 是**加载访谈纪律，不是派 subagent**——调用方在自己的上下文里跑轮次，
只有查事实时才派 subagent。
